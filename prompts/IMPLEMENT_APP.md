# Claude Codeへの実装依頼

この一式を置いたフォルダ（またはリポジトリ）でClaude Codeを開き、下記の指示を貼り付けます。

全体を一度に頼むと作業量が大きく、途中で文脈が溢れて品質が落ちやすいため、フェーズごとに分けて送ります。1つのフェーズが終わり、報告を確認してから次を送ってください。フェーズの区切りで新しいセッションを始めても、`CLAUDE.md`と`docs/08`のチェック状況から続きを再開できます。

## 共通の前置き（各フェーズの指示の先頭に付ける）

```text
CLAUDE.mdとREADME.mdを読み、docs/08_IMPLEMENTATION_PLAN.mdで進み具合を確認してください。
まず既存のファイルとGit状態を確認し、既存の変更を保持してください。
今回は下記のフェーズだけを実装・検証し、完了したらdocs/08のチェックを更新して報告してください。
GitHubへのpush・PR作成・公開は行わないでください（ローカルのコミットは可）。
不明な中国語レベル・検定級・目標日・ご家族の事情は作り上げず、文書の既定値か未設定として扱ってください。
```

## フェーズ1: 基盤・教材契約

```text
フェーズ1を実装してください。
- 空のフォルダならdocs/02の推奨構成（React + TypeScript + Vite、idb、Ajv、Vitest、Playwright）でプロジェクトを作成する。
- npm run lint / typecheck / test:unit / build / test:e2e のスクリプトを用意する。
- docs/05に沿って教材の型、schemas/content-pack.schema.json、意味上の検査を実装し、examples/starter-pack.jsonが検査を通ることをテストする。
- docs/04のIndexedDBストア、マイグレーション、初期教材登録、Repositoryを実装する。
- Hashルーティング、共通レイアウト（5ナビ）、設定、空/エラー状態を用意する。
- Viteのbaseを設定で変えられるようにし、サブパス配信に備える。
完了目安: サンプルJSONが検査・保存され、再読み込みで重複しない。
```

## フェーズ2: 日々の演習・復習

```text
フェーズ2を実装してください。
- 選択式・並べ替え・穴埋めの採点（docs/05の正規化・同字タイル規則を含む）を純粋関数で実装する。
- docs/06の復習ロジックを純粋関数で実装し、T03〜T06・T25の単体テストを書く。同日の連続正解だけで克服済みにしない。
- 今日の学習、即時再挑戦（各問題1回）、苦手一覧、ブックマーク、テーマ・形式・難易度の絞り込みを実装する。
- 回答保存はsubmissionIdで二重送信を防ぎ、履歴・学習状態・セッション位置を1トランザクションで更新する。
- セッション再開と、初回正答率・再挑戦結果を分けた結果表示を実装する。
完了目安: 不正解→翌日以降の復習→克服→再不正解まで一貫して動く。
```

## フェーズ3: 会話・教材拡充

```text
フェーズ3を実装してください。
- 場面一覧・詳細、ピンイン/訳の表示切り替え、返答を隠して考える会話練習、「言えた/少し迷った/言えなかった」の自己評価を実装する。自己評価は正答率に混ぜない。
- docs/10に沿って初期パックcore-familyの6シーンを作成する。各シーン4発言以上、重要表現6件以上、8問（選択4・並べ替え2・穴埋め2）、計48問。
- 中国語・ピンイン・日本語訳・正解・解説の対応を1件ずつ点検し、点検結果を報告する。
- 音声再生と「音声未収録」表示を実装する。権利と出典を確認できる音声がなければ収録せず、未収録と報告する。
完了目安: 結婚の挨拶などの教材に辿り着き、関連問題を解ける。
```

## フェーズ4: 追加・更新・復元

```text
フェーズ4を実装してください。
- 教材JSONと音声ファイルの選択、全件検査、差分プレビュー（新規/更新/変更なし/古いrevision/エラー）、一括適用を実装する。
- revision別の本文保存、旧revisionの履歴保持、他パックとのID衝突エラーを実装する。
- docs/04のバックアップ書き出し・検査・置き換え復元を実装する。失敗時は既存データを残す。
- T07〜T16のテストを書き、容量不足・保存途中の失敗・複数タブ・二重送信を検証する。
完了目安: 別途生成した教材を追加でき、失敗時にも既存データが保持される。
```

## フェーズ5: オフライン・仕上げ

```text
フェーズ5を実装してください。
- PWA・Service Worker・同梱資産キャッシュ・「オフライン利用可能」の準備状態表示を実装する。
- 本番ビルドを/repository-name/のようなサブパスで配信してE2Eを行い、T17〜T19・T23を確認する。
- E2Eで同一origin以外へのHTTP要求が0件であることを確認する（T18）。
- 幅360px、キーボード、IME、色以外の正誤表示を確認する（T21）。
- .github/workflows/ci.ymlをdocs/09に沿って作成する（実行はGitHubへ送るまで未実施と記載）。
- READMEを実際の起動・検証・ビルド手順に更新する。
- 最後にCLAUDE.mdの「検証と完了」に沿って、全体の報告をまとめる。
```

## GitHub反映まで依頼する場合の追加指示

リポジトリを用意した後、必要なときだけ、実在の情報に置き換えて最後に添える。共通の前置きの「push・PR作成・公開は行わない」の行は削除する。

```text
対象リポジトリは <owner/repository> です。
作業ブランチ <branch-name> を作り、変更をコミットしてpushし、<base-branch>向けのドラフトPRを作成してください。
PRには変更内容、検証結果、未完了事項を記載してください。GitHub Pagesの公開設定は行わないでください。
```

サイトの公開まで依頼する場合は、公開先・公開範囲を別途指定する。
