# GitHub・Claude Code運用

## リポジトリへの配置

この一式を対象リポジトリのルートに配置する。ルートにCLAUDE.md、README.md、docs/、prompts/、examples/、.github/がある構成にする。

既存リポジトリではREADMEとCLAUDE.mdを統合し、既存のビルド環境やユーザーの編集を保持する。新規リポジトリならこの一式を最初の設計ドキュメントとして登録できる。

この文書には実在するリポジトリ名・ブランチ名・URLを推測で記載しない。送信先が指定された時点でそのリポジトリを確認する。

## Claude Codeへの指示

[実装依頼プロンプト](../prompts/IMPLEMENT_APP.md)をフェーズごとに使う。フェーズを分けても、フェーズ間の整合性を維持して実装する。既存の作業ルールに従い、差分と検証結果をレビュー可能な形にする。

GitHubリポジトリがない段階ではローカルフォルダで実装し、ローカルのコミットだけを行う。依頼内容がローカル実装だけならローカルに成果を作る。ブランチ送信やPR作成まで依頼されている場合は、その範囲で進める。GitHubにコードを保存することと、Pagesで公開することは別の操作として扱う。

## 実装時に用意するCI

初期の文書一式にはアプリ用package.jsonがないため、CIのYAMLはまだ作らない。実装時に以下を満たす`.github/workflows/ci.yml`を作る。

- push/pull_requestを対象に、依存パッケージをlockfileからインストール。
- `npm run lint`、`npm run typecheck`、`npm run test:unit`、`npm run build`を実行。
- Playwrightのブラウザを用意し、本番ビルドで`npm run test:e2e`を実行。
- CIの権限は必要最小限のreadを既定とする。
- 失敗したテストの診断資料を残す。私的な学習データをアーティファクトに含めない。

依存取得やGitHub Actionsの通信は開発・検証環境の処理であり、アプリ実行時の外部API利用には含めない。

## Git管理対象

含める: アプリコード、型、スキーマ、公開可能な初期教材、文書、テスト、lockfile。

除外する: node_modules、dist、個人バックアップ、私的な教材・録音、秘密情報、ローカル設定、テスト生成物。実装時に.gitignoreを整える。公開教材は配布可能性と音声ライセンスを確認する。

## 任意のGitHub Pages公開

公開する場合の要件:

1. 利用者の指定したリポジトリと公開設定を確認する。
2. Viteのbaseを実際の公開パスに合わせる。ユーザー/組織のルートサイトとプロジェクトサイトを区別する。
3. build成果物だけを配信する。履歴はIndexedDBに残しサーバーへ送らない。
4. サブパスの音声・Service Worker・オフライン動作を確認する。
5. 公開後のURLと検証範囲を報告する。

GitHub Pages上のページ・同梱教材の閲覧制限は、リポジトリをprivateにしただけでは保証されない。認証のない本設計で「自分しかページを開けない」と説明しない。個人の学習履歴は公開リポジトリに含めない。

公開URLが変わるとブラウザの保存領域も変わるため、移行時は旧URLでバックアップを書き出し、新URLで取り込む。
