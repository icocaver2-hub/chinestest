## 判断の記録

実装中に既定値から外れた判断、仕様の矛盾への対処を、日付（Asia/Tokyo）・内容・理由の形で追記する。

| 日付 | 内容 | 理由 |
| --- | --- | --- |
| 2026-11-01 | 初期教材の登録済み判定は、`meta`ではなく`packs`ストアに`core-family`が存在するかで行う | バックアップは`meta`を含まないため、復元後に初期教材が二重登録されるのを防ぐ（04の復元仕様との整合） |
| 2026-11-01 | 未学習の問題に初回正解した場合の次回復習は翌日（06の表のとおり）。3日・7日・14日の間隔は、期限到来後の復習で正解した場合に適用する | 依頼文の「1回目は3日後」は復習での正解を指すと解釈した。異なる場合はユーザーの指示で変更する |
| 2026-11-01 | TypeScriptは7系ではなく6.0系を採用 | typescript-eslintの対応範囲が`<6.1.0`のため。対応後に更新を検討する |
| 2026-11-01 | JSON SchemaはAjvで実行時コンパイルせず、`scripts/generate-validator.mjs`で検査関数を生成してコミットする（`npm run lint`と単体テストでスキーマとの一致を確認） | 本番ビルドにCSP（`script-src 'self'`）を付けて外部通信を遮断するため。Ajvの実行時コンパイルは`new Function`を使いCSPと両立しない |
| 2026-11-01 | CSPのmetaタグは本番ビルドのみに付与する | 開発サーバーはインラインのHMRスクリプトを使うため |
| 2026-11-01 | フェーズ1では同梱教材としてサンプル（`sample-meal`）を`public/content/index.json`経由で登録する。初期パック`core-family`はフェーズ3で追加する | フェーズ1の完了目安（サンプルJSONの検査・保存・重複なし）を実際の起動経路で確認するため。`core-family`追加時にサンプルを同梱から外すかはフェーズ3で判断する（取り込みを暗黙の削除にしない方針のため、登録済み利用者のサンプルは残る） |
| 2026-11-01 | 登録済みの同梱パックは起動時に一切書き換えない。同梱教材の更新差分プレビュー（02「起動」4）はフェーズ4で実装する | 初期教材の再配信で利用者の教材や履歴を上書きしないため |
| 2026-11-01 | シーン・問題レコードに登録順`seq`（metaの`nextSeq`で採番）を追加 | 06「今日の学習の選び方」の「教材の登録順」をIndexedDBで再現するため |
| 2026-11-01 | 問題の学習状態（questionStates）は最初の回答時に04の初期値で作成する（登録時には作らない） | 未学習と回答済みを区別しやすく、教材登録のトランザクションを小さく保つため。実装はフェーズ2 |
| 2026-11-01 | 設定の保存は不正な値を含むと全体を拒否する（既定値への置き換えで保存済みの値を上書きしない） | 誤入力で既存の設定が失われないようにするため |
| 2026-11-01 | `@playwright/test`は1.63.0に固定 | 作業環境に導入済みのChromiumと版を合わせるため。CIでは`npx playwright install`で同じ版のブラウザを取得する |
| 2026-11-01 | 開発用依存のminimatchを`overrides`で11系に固定 | `npm audit`で報告されたeslint経由の脆弱性（開発時のみ）を解消するため |
| 2026-11-01 | ホーム初回の目的・問題数・表示設定の簡易設定（03「ホーム」）はフェーズ1では未実装。設定画面で同じ項目を変更できる | フェーズ1の作業範囲外のため。フェーズ2以降でホームに追加する |
| 2026-11-03 | 利用者の希望によりGitHub Pages公開用ワークフロー（`.github/workflows/deploy-pages.yml`）をフェーズ5より前に追加。`main`へのpushで検証・ビルド・公開する。E2Eは公開ワークフローでは実行しない（フェーズ5のCIで追加） | スマートフォンから早く利用するため。配信パスは`actions/configure-pages`の`base_path`を`BASE_PATH`に渡して決める。Pagesの有効化（Settings → Pages → Source: GitHub Actions）とリポジトリの公開範囲は利用者が設定する |
| 2026-11-03 | 公開リポジトリ`icocaver2-hub/chinestest`へ、過去の履歴を持ち込まずに移行。文書中の利用目的は「パートナーのご家族」との会話という一般的な表現にした | GitHub Pagesを無料で使うためリポジトリを公開にする一方、個人的な事情やメールアドレスを公開の履歴に残さないため |
